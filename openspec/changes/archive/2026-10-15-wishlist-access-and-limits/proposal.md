# Proposal

## Why

Решения пользователя по оставшимся наблюдениям spec `wishlists` (2026-10-15):
- OBS-07: продавец (роль SELLER) не создает и не использует вишлисты;
- OBS-08: лимиты — 20 вишлистов на пользователя и 200 товаров в вишлисте, с
  защитой от одновременных запросов;
- ASM-04: удаление товара из вишлиста не зависит от доступности каталога;
- OBS-09, ASM-03: удалить неиспользуемые методы репозитория и устаревшее
  предположение spec.

Отдельный аккаунт продавца только с ролью SELLER — change
`separate-seller-account`. У новых аккаунтов продавца роли USER нет, поэтому
вишлисты им недоступны и без этого change; правило «SELLER → 403» здесь нужно
существующим продавцам, у которых на аккаунте покупателя USER и SELLER
(решение пользователя: оставить их как есть).

OBS-05 (удаленные из каталога товары) — отдельный change `product-deletion-sync`
(новое событие между сервисами), ASM-01 (issuer JWT) — отдельный change
`user-service-jwt-issuer`.

## What Changes

- `/wishlists/**`: JWT с ролью SELLER получает 403, даже если в нем есть USER
  или ADMIN. Вишлисты продавцов не удаляются — становятся недоступны, пока у
  аккаунта есть SELLER. **Изменение доступа.**
- Создание вишлиста сверх 20 у пользователя и добавление товара сверх 200 в
  вишлисте — 409. Существующие данные сверх лимита не меняются, блокируется
  только рост.
- `DELETE /wishlists/{id}/products/{productId}`: если каталог недоступен,
  товар все равно удаляется, ответ 200 с вишлистом без данных товаров
  (`products = []`); остальные id в вишлисте остаются.
- Удаляются `findByName` и `findByKeycloakUserIdAndNameContainingIgnoreCase`
  (OBS-09); ASM-03 снимается из spec.
- Не входят: изменения frontend (он показывает вишлисты всем вошедшим —
  продавец увидит ошибку 403), OBS-05, ASM-01.
