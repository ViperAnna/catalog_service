# Proposal

## Why

Ответы об ошибках вишлистов противоречат остальному API user-service и
собственной spec `wishlists` (OBS-03, OBS-04, OBS-06):
- ошибки каталога («товар не найден», «каталог недоступен») возвращаются со
  стандартным телом Spring без `{message, time}`, а сообщение
  `PRODUCT_NOT_FOUND` содержит литерал `[%s]`;
- удаление отсутствующего в вишлисте товара дает 409 с текстом «not found»,
  а объявленное сообщение `WISHLIST_ITEM_NOT_FOUND` не используется;
- при переименовании проверка имени выполняется раньше проверки владения,
  поэтому несуществующий или чужой вишлист может дать 409 вместо 404, что
  противоречит requirement `Wishlist API access and ownership`.

## What Changes

- Ошибки каталога при работе с вишлистами возвращаются с телом
  `{message, time}`; коды не меняются (404 и 503). Сообщение «товар не найден»
  содержит id товара.
- `DELETE /wishlists/{id}/products/{productId}` для товара, которого нет в
  вишлисте: 404 вместо 409, сообщение `Product with id [<id>] not found in
  wishlist.` **Изменение кода ответа** (frontend коды ответов вишлистов не
  разбирает — проверено, везде общий `catch`).
- `PUT /wishlists/{id}`: сначала существование и владение (404), затем
  уникальность имени (409). **Изменение кода ответа** только для
  несуществующего или чужого вишлиста при занятом имени.

Не входят (отложены, см. ниже): OBS-01, OBS-02, OBS-05, OBS-07, OBS-08, OBS-09.

## Capabilities

### New Capabilities
<!-- нет -->

### Modified Capabilities
- `wishlists`: коды и тело ошибок при добавлении и удалении товара и
  переименовании, формат ошибок каталога.

## Impact

- Код user-service: `GlobalExceptionHandler`, `CatalogClient`,
  `WishlistServiceImpl`, `MessageKeys`. Схема БД, другие сервисы, frontend и
  настройки тестов (`skipTests`) не меняются.
- API: тела ошибок каталога и два кода ответа (см. выше). Успешные ответы не
  меняются.

## Deferred observations

| OBS | Почему не в этом change |
|---|---|
| OBS-01 ответ на создание без вишлиста | изменение тела успешного ответа (контракт); варианты: добавить поля к `{message, time}` или вернуть вишлист — решение пользователя |
| OBS-02 уникальность имени без учета регистра и индекса | бизнес-решение OQ-03 и миграция существующих данных (возможны дубли); при `ddl-auto` индекс на существующей таблице сам не появится (см. `user-contact-uniqueness`) |
| OBS-05 productCount и удаленные товары | бизнес-решение OQ-02 (очищать id или считать только доступные) |
| OBS-07 статус товара | фактически устранено change `seller-store-lifecycle`: `GET /products/{id}` возвращает 404 для недоступного товара; остаток — продавец-владелец может добавить свой недоступный товар (каталог отдает его владельцу); решение OQ-04 |
| OBS-08 ограничения БД и лимиты | миграция `wishlist_products` (PK/UNIQUE) и бизнес-решение о лимитах |
| OBS-09 неиспользуемые методы репозитория | практической пользы нет: на поведение не влияют |

После archive в spec `wishlists` нужно обновить non-normative секцию: OBS-03,
OBS-04, OBS-06 — устранены; OBS-07 — уточнить остаток.
